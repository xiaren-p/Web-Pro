# 菜单管理

「系统 → 菜单管理」维护系统的菜单树与动态路由，菜单是前端导航与权限控制的基石。后端端点前缀 `/api/v1/menus`。

## 页面入口

侧边栏：系统 → 菜单管理（路由 `/system/menu`）。

## 菜单类型

| 类型 | 值 | 说明 |
| --- | --- | --- |
| 目录 | 1 | 仅分组节点，不对应页面 |
| 菜单 | 2 | 对应一个路由页面 |
| 按钮 | 3 | 页内操作权限点（如「新增」「删除」），不显示在导航中 |
| 外链 | 4 | 外部链接，转内部占位路径 + meta.link |

## 表格列（树表）

菜单名称（含图标）、类型（目录 / 菜单 / 按钮 / 外链）、路由名称（仅菜单）、路由路径、组件路径、权限标识（仅按钮）、状态（显示 / 隐藏）、排序、操作列。

## 搜索

菜单名称（模糊，匹配 name / path / component / perms）。

## 新增 / 编辑表单字段

| 字段 | 必填 | 显示条件 | 说明 |
| --- | --- | --- | --- |
| parentId | 是 | 始终 | 父级菜单（树选择），顶层选「顶级菜单」 |
| name | 是 | 始终 | 菜单名称 |
| type | 是 | 始终 | 目录 / 菜单 / 按钮 / 外链，默认菜单 |
| path（外链） | — | type=4 | 外链地址 |
| routeName | 是 | type=2 | 路由名称，与 `defineOptions name` 一致以开启缓存 |
| path（目录/菜单） | 是 | type=1/2 | 目录以 `/` 开头，菜单不用 |
| component | 是 | type=2 | 相对 `src/views/`，如 `system/user/index` |
| visible | 是 | 始终 | 显示 / 隐藏，默认显示 |
| sort | 否 | 始终 | min 0，默认 1 |
| perms | 否 | type=3 | 权限标识，如 `sys:user:add` |
| icon | 否 | type≠按钮 | 支持 `el-icon-xxx` / `tabler:xxx` / svg |

类型切换逻辑：目录切菜单清空 component；非按钮类型清空 perms。编辑时父级不能为自身。

## 动态路由

前端登录后调 `GET /menus/routes` 获取路由树：

- 超管 / 公司管理员 → 全量启用菜单。
- 其他 → 岗位关联菜单 + 向上补全父级。
- 按钮类型跳过。
- 外链转内部 `/ext-{id}` 路径 + `component="external/redirect"` + `meta.link`。
- 目录无 component 用 `Layout`。

## 操作

- **新增**：工具栏或行内「新增」（父级 = 当前行，仅目录 / 菜单）→ 填写 → 确定。
- **编辑**：行内编辑 → 回填 → 修改 → 确定。
- **删除**：行内删除 → 确认（存在子菜单禁止删除）。

## 同步菜单

部署或菜单变更后，在服务器执行 `python manage.py sync_system_menus` 同步内置菜单与按钮权限，清理历史残留。
