# 岗位管理

「系统 → 岗位管理」维护岗位并为其分配菜单权限。本系统中**岗位承载菜单权限**（替代传统角色），用户通过所属岗位获得对菜单与按钮的访问权。后端端点前缀 `/api/v1/positions`。

## 页面入口

侧边栏：系统 → 岗位管理（路由 `/system/position`）。

## 表格列

岗位名称、岗位编码、所属部门、状态（正常 / 禁用）、排序、操作列（分配权限 / 编辑 / 删除）。

- 分配权限：公司管理员或部门管理员可操作，非内置岗位。
- 编辑 / 删除：仅公司管理员可操作，内置岗位不可删。

## 搜索

关键字（岗位名称 / 编码）。

## 新增 / 编辑表单字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| deptId | 否 | 所属部门 |
| name | 是 | 岗位名称 |
| code | 是 | 岗位编码（英文 / 下划线），unique |
| status | 是 | 正常 / 停用，默认正常 |
| sort | 否 | 排序，min 0，默认 1 |
| remark | 否 | 备注，最多 200 字 |

## 菜单授权

点击「分配权限」打开授权抽屉：

- 顶部：权限名称搜索 + 展开 / 收缩按钮 + 「父子联动」复选框（默认勾选）。
- 主体：菜单树（`show-checkbox`），勾选该岗位可访问的菜单与按钮权限。
- 数据源：`MenuAPI.getAssignableOptions()`（公司管理员 / 超管全量，其他返回自身岗位菜单范围）。
- 提交：取选中 + 半选节点 ID → `PUT /positions/<id>/menus`（覆盖更新）。
- **内置岗位**：确定按钮禁用 + tooltip「内置岗位拥有全部权限，不可修改」。

## 内置岗位保护

`is_builtin=True` 的岗位（如 `sys_admin`）：

- 不可删除。
- 不可手动分配给用户。
- 菜单权限不可修改（返回全量菜单 ID）。
- admin 账号的岗位绑定不可修改。

## 权限机制

- 每个菜单项带有 `perms` 标识（如 `sys:user:add`）。
- 用户登录后，后端根据其岗位聚合所有 perms，前端动态路由据此渲染可见菜单与按钮。
- 后端接口由 `menu_perm_required.py` 权限类校验 perms。
- 非超管用户加载路由时，岗位关联菜单会向上补全所有父级菜单，保证路由树完整性。

## 下拉接口

`GET /positions/options`：仅启用 + 非内置岗位；部门管理员仅本部门及子部门。
